## 章节明细（含全部示例与已验证输出）

### 0. 开胃菜：怎么跟着学

- 安装 CLI：`pnpm add -g @andares/promptdown`（或装 `.vsix` 用 VSCode 高亮）
- 两个命令：`pd2json <file.pd> [段名]`（转 JSON）、`pdformat <file.pd> -w`（格式化）
- 建议：每节例子存成 `x.pd` 跑一遍 `pd2json x.pd`

### 1. 纯文本：先写出第一份 .pd

示例：

```pd
你好，世界
这是第二行
```

```bash
pd2json hello.pd
```

```json
{"Subject1":{"Info1":["你好，世界","这是第二行"]}}
```

讲解：

- 最朴素的 `.pd` 就是一叠文本行
- 顶层**没有键**的内容自动收进匿名容器 `Subject1`（Subject = 顶层匿名对象根）
- 行文压进 `Info1` 数组（Info = 块内匿名数组）；数组元素一行一个、无逗号
- 空行无视：`name:` 下空 3 行再写内容，仍是同一个 Info 数组（已验证：`{"name":{"Info1":["a","b"]}}`）
- 预告：下一节给文本"起名字"

### 2. 顶层键值：给文本起名字

示例：

```pd
标题: 我的提示词
```

```json
{"标题":"我的提示词"}
```

讲解与坑：

- 规则：**行内第一个半角冒号**把行分成键和值
- **折叠规则第一课**：键内只有单条内容 → 直接折叠成字符串 `"key": "value"`
- `标题:`（空值）→ `{"标题":{}}` 空对象（已验证）
- 键名可以含空格（`bad key: v` 合法，已验证），但不能以空白/冒号开头、键内不能再有冒号
- ⚠️ 坑 1：**全角冒号不是键值**！`标题：内容` 被当成普通文本（parser 只认半角 `:`，已验证 → `{"Subject1":{"Info1":["标题：内容"]}}`）
- ⚠️ 坑 2：**冒号后无空格不是键值**！`clock:12:30` 值是文本（值必须以空白开头，已验证）
- 兜底：`pdformat -w` 会自动把 `键：值` / `键:值` 修成 `键: 值`；但手写规范请直接 `键: 空格值`

### 3. 顶层键值下放多行文本：三种写法（等价）

**写法 A：直接跟在冒号后面（同行写第一行，换行续写）**

```pd
描述: 第一行
第二行
第三行
```

```json
{"描述":{"Info1":["第一行","第二行","第三行"]}}
```

**写法 B：冒号后回车，后续裸文本行**

```pd
描述:
第一行
第二行
```

```json
{"描述":{"Info1":["第一行","第二行"]}}
```

**写法 C：回车换行 + `-` 前缀**

```pd
描述:
- 第一行
- 第二行
```

```json
{"描述":{"Info1":["第一行","第二行"]}}
```

讲解：

- **三种写法 JSON 完全等价**（均已验证）——`-` 与裸行在"找爸爸"时地位相同
- **折叠规则第二课**：一旦有续行（≥2 条内容），就不再折叠成字符串，变成 `对象 + Info1 数组`；只有"同行单条"才折叠
- 缩进宽容：顶层键下的内容行/`-`行**缩不缩进都归该键**（`描述:\n  - 第一行` 已验证同结果）
- 怎么选：同行写法省行数；`-` 写法列表感强（后面章节会看到它还是"子键值"的唯一入口）；裸行最省事
- 🎯 要点：单行 → 字符串；多行 → Info 数组

### 4. 顶层键值下放多个键值 + 与文本混排

**子键值必须用 `-`（核心规则：裸键值行"不找爸爸"，永远在根层开新键）**

```pd
任务:
- 目标: 做早餐
- 步骤:
  - 煎蛋
  - 热牛奶
```

```json
{"任务":{"目标":"做早餐","步骤":{"Info1":["煎蛋","热牛奶"]}}}
```

⚠️ 最易踩的坑（已验证）：裸键值行缩进再深也**回根**，不会进 `任务`：

```pd
任务:
 目标: 做早餐      # 裸键值，不找爸爸
```

```json
{"任务":{},"目标":"做早餐"}
```

**文本与键值混排（Info 分段）**：

```pd
任务:
先说
- 目标: 做早餐
再说
```

```json
{"任务":{"Info1":["先说"],"目标":"做早餐","Info2":["再说"]}}
```

- Info 分段规则：键值插在文本中间 → 文本被拆成 Info1 / Info2，编号自增；**编号每层独立**
- 键值 + 子键 + 文本 + 嵌套四合一（对应 SPEC 范例 1，已验证）：

```pd
name1:
- some
- name2: other words
- name3:
  - more
  - words
words
```

```json
{"name1":{"Info1":["some"],"name2":"other words","name3":{"Info1":["more","words"]},"Info2":["words"]}}
```

- 无限嵌套：`- 键:` 链一层层加深（`项目: - 模块A: - 接口: - GET /api` → `{"项目":{"模块A":{"接口":{"Info1":["GET /api"]}}}}`，已验证）
- 🎯 要点：顶层键下"子键值"入口 = `-`；文本与键值混排 → Info 分段

### 5. 引用：多段混排复用

场景：提示词里一段公共设定被多处引用。**段标记 `//!pd 名称` + 引用 ` :名称 `（前后必须带空格）**。

**纯文字引用 → 内联嵌入**（已验证）：

```pd
//!pd 设定
快走，别回头

//!pd 台词
台词: 她说 :设定 了吗
```

```bash
pd2json file.pd 台词
```

```json
{"台词":"她说 快走，别回头 了吗"}
```

**结构化引用 → 块嵌入**（被引段带键值/序列时，整段作为块插进来，已验证）：

```pd
//!pd 基础设定
- 语言: TypeScript
- 目标: 实现一个带防抖的搜索框

//!pd 任务
任务:
- 技术栈: React
- 参考: :基础设定
```

```bash
pd2json file.pd 任务
```

```json
{"任务":{"技术栈":"React","参考":{"语言":"TypeScript","目标":"实现一个带防抖的搜索框"}}}
```

规则要点：

- 引用名支持中文；**不能以 `-` 开头**（`:-` 保留给转义，见第 7 节）
- 多段文件**必须指定段名**，否则报错（`pd2json file.pd 任务`）
- 引用在**编译期**内联展开，支持嵌套；段不存在 / 循环引用 / 嵌套过深（>32）都会报错
- 混输场景：`//!pd` 之前的普通提示词被丢弃（preamble），`//!pd` 之后才按 pd 解析
- 带语法标记的引用会把所在行**断开转成 `-` 项 + 块嵌入**（引用前后文本各自成 `-` 项；可引用 SPEC 范例 4 作进阶图）

### 6. 代码块（Code 支持）

围栏 ```` ```lang ```` ... ```` ``` ````（已验证）：

```pd
name:
```js
const x = {a: 1};
  const y = 2;
```

```

```json
{"name":{"Code1":{"lang":"js","body":"const x = {a: 1};\n  const y = 2;"}}}
```

要点（全部已验证）：

- 围栏内**原样保留**：缩进、换行、冒号、`-` 一律不参与解析，也不被 pdformat 改动
- `lang` 可省略：无 lang → 输出**只有 `body`** 字段；`body` 是单个字符串（含换行），不按行拆数组
- **归属简化**：代码块只能属于顶层（顶层键或 Subject）；嵌套块（`- sub:`）内出现的代码块**仍归顶层键**
- 未闭合围栏 → body 延伸到文件尾（宽容处理，不报错）
- 打断 Info 段：`- some` + 代码块 + `words` → `Info1` / `Code1` / `Info2` 三段
- 键内有代码块 → 不再折叠（`name: value` + 代码块 → 对象形态）
- 顶层无键的代码块 → 归 `Subject1`
- 多个代码块编号递增：Code1 / Code2（每层独立）

### 7. 行内多冒号的处理

**只有第一个冒号是键值分隔符**（已验证）：

```pd
url: https://example.com:8443/path
```

```json
{"url":"https://example.com:8443/path"}
```

值里的后续冒号全部是普通文本，不会再开启键值。

**`:-` / `：-` 整行转义**：行内出现 `:-` 或 `：-` → 整行不识别任何键值（已验证）：

```pd
clock:- 12:30
```

```json
{"Subject1":{"Info1":["clock:- 12:30"]}}
```

用途：防止"时钟时间 + 列表"被误解析；两个字符原样保留。

**转义不影响同行的引用**（已验证）：

```pd
//!pd base
hello world
//!pd main
clock:- 12:30 :base done
```

```bash
pd2json file.pd main
```

```json
{"Subject1":{"Info1":["clock:- 12:30 hello world done"]}}
```

- 🎯 要点：键值分隔 = 第一个半角冒号；引用识别独立于键值规则（前后带空格的 ` :ref ` 永远按引用处理）

### 8. 分隔线 `---`

作用：**块边界，指针回根**——清掉之前所有父子关系（已验证）：

```pd
第一部: 内容
---
第二部: 内容
```

```json
{"第一部":"内容","第二部":"内容"}
```

分隔线后的无键内容 → 新 `Subject2`（已验证，对应 SPEC 范例 3）：

```pd
no man
can
kill: me
---
nobody
- like: you
```

```json
{"Subject1":{"Info1":["no man","can"]},"kill":"me","Subject2":{"Info1":["nobody"],"like":"you"}}
```

对比记忆：**空行无视**（空多少行都继续找爸爸），**`---` 强制回根**。
使用场景：一份文件写多个互相独立的块。

### 9. 其他组合与易踩坑（用户没想到的）

逐条给出"现象 + 原因 + 对策"（全部已验证）：

1. **顶层 `-` 不能缩进**：文件开头或 `---` 后的 `- xxx` → 语法错误"顶层 `-` 不允许缩进"（pd2json 报错退出；pdformat 自动去缩进修正）
   - 但注意：**顶层键下的 `-` 缩不缩进都行**（归键块，不是顶层）
2. **裸键值行不找爸爸**：缩进再深也回根（见第 4 章反例）；要嵌套必须 `- 键:`
3. **全角冒号 / 无空格冒号不是键值**（见第 2 章）；`pdformat` 可一键修正
4. **重复键 → 后者覆盖前者**（`name1: a` + `name1: b` → `{"name1":"b"}`）
5. **空值键 `key:` → 空对象 `{}`**（不是 null、不是空串）
6. **`key: 值` 之后只要出现续行/子键/代码块 → 不再折叠成字符串**，统一对象形态
7. **引用名不能以 `-` 开头**；多段文件不指定段名 → 报错"必须指定段名"
8. **Subject vs Info**：Subject = 顶层匿名对象容器（Subject1/Subject2…）；Info = 块内匿名数组（Info1/Info2…）；编号各自独立
9. **内联 markdown 原样保留**：`**粗体**`、`` `代码` `` 转 JSON 时不解析不剥离
10. **无限嵌套**：靠 `- 键:` 链；数组元素一行一个、无逗号
11. **段落结构**：没有 `---` 时，空行随便空，结构不变
12. 代码块相关坑位汇总（见第 6 章）：只归顶层、打断 Info、未闭合宽容

| 写法 | 含义 | JSON 结果 |
| --- | --- | --- |
| `//!pd 名称` | 段标记（可省略） | — |
| `---` | 分隔线，指针回根 | 新块 / 新 Subject |
