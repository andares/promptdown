# promptdown 新手教程（喂饭版）

> promptdown（`.pd`）是一种极简标记语言：核心符号只有 `:`（键值/引用）和 `-`（序列标记），
> 兼容 markdown 风格，可以一键转成 JSON。
>
> 本教程是 [`SPEC.md`](./SPEC.md) 的"人话版"：每一节都给出 **写法 → 命令 → JSON 输出** 三段对照，复制即跑。
> 所有示例的输出均用真实 parser（v0.2.3）验证过；与 SPEC 冲突时以 SPEC 为准。

## 开胃菜：怎么跟着学

写 `.pd` 不需要特殊环境——它就是文本文件（VSCode 装上本项目的扩展即可获得语法高亮）。
转 JSON 只需要一个命令行工具：

```bash
# 全局安装（提供 pd2json / pdformat 两个命令）
pnpm add -g @andares/promptdown

# 转 JSON（单段文件可省略段名；多段文件必须指定）
pd2json 你的文件.pd [段名]

# 格式化：自动修正全角冒号、冒号空格、顶层缩进（-w 写回原文件）
pdformat 你的文件.pd -w
```

> 💡 **跟着练**：每节遇到 `.pd` 示例，就存成 `demo.pd` 跑一遍 `pd2json demo.pd`，亲眼看到输出。
> 本教程所有示例的输出都已经过验证，你可以直接对照。

## 纯文本：先写出第一份 .pd

**你想做什么**：什么都不管，先写几行字。

```pd
你好，世界
这是第二行
```

```bash
pd2json hello.pd
```

```json
{
  "Subject1": {
    "Info1": [
      "你好，世界",
      "这是第二行"
    ]
  }
}
```

**一句话规则**：最朴素的 `.pd` 就是一叠文本行。顶层**没有键**的内容自动收进匿名容器 `Subject1`（Subject = 顶层匿名对象根），行文压进 `Info1` 数组（Info = 块内匿名数组）。

- 数组元素**一行一个**，不需要逗号
- **空行无视**：下面这个文件中间空了三行，输出和上面完全一样

```pd
你好，世界


这是第二行
```

```json
{
  "Subject1": {
    "Info1": [
      "你好，世界",
      "这是第二行"
    ]
  }
}
```

🎯 **本节要点**：`Subject1` + `Info1` 是"没有键的文本"的默认归宿；空行不影响结构。

## 顶层键值：给文本起名字

**你想做什么**：给一段文本起个名字（键），让输出变成结构化 JSON。

```pd
标题: 我的提示词
```

```bash
pd2json hello.pd
```

```json
{
  "标题": "我的提示词"
}
```

**一句话规则**：**行内第一个半角冒号**把一行拆成键和值；写在文件顶层 → 直接成为 JSON 根键。

- **折叠规则第一课**：键内只有**单条**内容 → 直接折叠成字符串 `"key": "value"`
- `标题:`（冒号后什么都没有）→ 空对象 `{}`（不是 null、不是空串）：

```json
{
  "标题": {}
}
```

- 键名可以含空格（`bad key: v` 是合法键值，键名就是 `bad key`），但**不能以空白或冒号开头，键内不能再有冒号**

> ⚠️ **坑 1：全角冒号不是键值**。`标题：内容` 用的是全角 `：`，parser 只认半角 `:`，整行被当成普通文本。中文用户最容易踩这个：
> `{"Subject1":{"Info1":["标题：内容"]}}`
>
> ⚠️ **坑 2：冒号后无空格不是键值**。`clock:12:30` 的值必须以空白开头才合法，无空格 → 整行是文本：
> `{"Subject1":{"Info1":["clock:12:30"]}}`
>
> 💡 **兜底**：`pdformat -w` 会自动把 `键：值` / `键:值` 修成 `键: 值`。但手写时请直接养成习惯：**`键: 空格值`**。

🎯 **本节要点**：`key: value` 在顶层创建根键；单条 → 字符串；半角冒号 + 冒号后有空格，缺一不可。

## 顶层键值下放多行文本：三种写法

**你想做什么**：`描述` 这个键下面放好几行文字。三种写法，**JSON 结果完全一样**。

### 写法 A：直接跟在冒号后面

第一行写在冒号后面，换行继续写：

```pd
描述: 第一行
第二行
第三行
```

```json
{
  "描述": {
    "Info1": [
      "第一行",
      "第二行",
      "第三行"
    ]
  }
}
```

### 写法 B：冒号后回车，换行写裸文本

```pd
描述:
第一行
第二行
```

```json
{
  "描述": {
    "Info1": [
      "第一行",
      "第二行"
    ]
  }
}
```

### 写法 C：回车换行 + `-` 前缀

```pd
描述:
- 第一行
- 第二行
```

```json
{
  "描述": {
    "Info1": [
      "第一行",
      "第二行"
    ]
  }
}
```

**一句话规则**：三种写法等价——`-` 开头和裸文本行在"找爸爸"时地位相同，都压进该键的 `Info1` 数组。

- **折叠规则第二课**：只要变成多行（≥2 条内容），就不再折叠成字符串，而是 `对象 + Info1 数组`。
  记住：**单行 → 字符串，多行 → Info 数组**。第 1 章的 `Subject1.Info1`、这里的 `描述.Info1`，是同一个机制。
- **缩进宽容**：顶层键下的内容行 / `-` 行，缩不缩进都归该键。下面这个文件输出与写法 C 完全相同：

```pd
描述:
  - 第一行
  - 第二行
```

- **怎么选**：
  - 写法 A：省行数，第一行顺带写完
  - 写法 B：最省事，纯文本直接回车换行
  - 写法 C：列表感最强，而且下一章会看到——`-` 还是"子键值"的唯一入口

🎯 **本节要点**：多行文本 = `Info` 数组；`-` 与裸行等价；缩进在顶层键下不敏感。

## 顶层键值下放多个键值 + 文本混排

**你想做什么**：`任务` 下面既有子键值，又有零散文字，还能一层套一层。

### 子键值必须 `-` 开头

顶层键下要放子键值，**必须写 `- 键: 值`**（`-` 后面跟一个空格）：

```pd
任务:
- 目标: 做早餐
- 步骤:
  - 煎蛋
  - 热牛奶
```

```json
{
  "任务": {
    "目标": "做早餐",
    "步骤": {
      "Info1": [
        "煎蛋",
        "热牛奶"
      ]
    }
  }
}
```

> ⚠️ **最易踩的坑：裸键值行"不找爸爸"**。下面这样写，`目标` 不会进 `任务`，而是**回根**变成顶层键：
>
> ```pd
> 任务:
>  目标: 做早餐
> ```
>
> ```json
> {
>   "任务": {},
>   "目标": "做早餐"
> }
> ```
>
> 原因：裸键值行（不带 `-`）永远在根层开新键，缩进再深也不嵌套。**要嵌套，必须 `- 键:`。**

### 文本与键值混排（Info 分段）

文字夹在键值中间 → 自动拆成 Info1 / Info2，编号自增：

```pd
任务:
先说
- 目标: 做早餐
再说
```

```json
{
  "任务": {
    "Info1": [
      "先说"
    ],
    "目标": "做早餐",
    "Info2": [
      "再说"
    ]
  }
}
```

- 编号规则：连续无键的文本压进同一个 Info；中间出现键值 → 新开一段，Info1 → Info2
- **编号每层独立**：`name.Info1` 和顶层 `Subject1.Info1` 互不干扰，都是各自层里的 1

### 键值 + 子键 + 文本 + 嵌套，四合一

```pd
name1:
- some
- name2: other words
- name3:
  - more
  - words
words
```

```json
{
  "name1": {
    "Info1": [
      "some"
    ],
    "name2": "other words",
    "name3": {
      "Info1": [
        "more",
        "words"
      ]
    },
    "Info2": [
      "words"
    ]
  }
}
```

注意最后一行 `words` 与 `- some` 同级 → 都进 `name1` 的 Info；而 `- name3:` 下的 `- more` 更深一层 → 进 `name3.Info1`。这就是"按缩进找爸爸"。

### 无限嵌套

`- 键:` 链想套多深套多深：

```pd
项目:
- 模块A:
  - 接口:
    - GET /api
```

```json
{
  "项目": {
    "模块A": {
      "接口": {
        "Info1": [
          "GET /api"
        ]
      }
    }
  }
}
```

🎯 **本节要点**：顶层键下"子键值"唯一入口 = `- 键:`；文本混排 → Info 分段；嵌套靠缩进，无限深。

## 引用：多段混排复用

**你想做什么**：一份文件里有"公共设定"，好几处都要用；改设定只改一处，引用处自动跟着变。

### 两个零件

- **段标记**：`//!pd 名称` 声明一个 pd 段
- **引用**：`:` 后面紧贴引用名（如 `:基础设定`）——这是 `:` 的第二种用法，**前后必须带空格**

### 纯文字引用 → 内联嵌入

被引用的段如果只有纯文字，直接"嵌"进当前位置，连前后空格都保留：

```pd
//!pd 设定
快走，别回头

//!pd 台词
台词: 她说 :设定 了吗
```

```bash
pd2json file.pd 台词
```

```json
{
  "台词": "她说 快走，别回头 了吗"
}
```

注意：这个文件有两个段，**必须指定段名**（`pd2json file.pd 台词`）；不指定会直接报错。

### 结构化引用 → 块嵌入

被引用的段带键值/序列（有语法标记）时，整段作为一块插进引用位置：

```pd
//!pd 基础设定
- 语言: TypeScript
- 目标: 实现一个带防抖的搜索框

//!pd 任务
任务:
- 技术栈: React
- 参考: :基础设定
- 额外要求: 防抖延迟 300ms
```

```bash
pd2json file.pd 任务
```

```json
{
  "任务": {
    "技术栈": "React",
    "参考": {
      "语言": "TypeScript",
      "目标": "实现一个带防抖的搜索框"
    },
    "额外要求": "防抖延迟 300ms"
  }
}
```

`参考` 的值就是被引段完整转出的对象。

### 引用在一行中间：前后文本断开成 `-` 项

引用出现在一行中间，且被引内容带语法标记 → 该行按引用位置断开，前后文本各自变成 `-` 项，被引段块嵌入：

```pd
//!pd a1
name1:
- some: words

//!pd a2
name3: no :a1 more
```

```bash
pd2json file.pd a2
```

```json
{
  "name3": {
    "Info1": [
      "no"
    ],
    "name1": {
      "some": "words"
    },
    "Info2": [
      "more"
    ]
  }
}
```

### 规则要点

- 引用名支持中文（上面的 `:基础设定`）；**不能以 `-` 开头**（`:-` 是转义标记，见"行内多冒号"一节）
- 引用在**编译期**内联展开，支持嵌套引用
- 三种报错：段不存在（`引用段不存在: xxx`）、循环引用（`循环引用: a -> b -> a`）、嵌套过深（>32 层）
- 混输场景：`//!pd` 之前的普通提示词会被丢弃（作为 preamble），`//!pd` 之后才按 pd 解析

🎯 **本节要点**：`//!pd 名称` 分段 + `:名称` 引用（前后空格）；纯文字内联、带结构块嵌入；多段必须指定段名。

## 代码块（Code 支持）

**你想做什么**：在提示词里贴一段代码/配置，要求**原样保留**，不被当成 pd 解析。

### 基本用法

````pd
name:
```js
const x = {a: 1};
  const y = 2;
```
````

```json
{
  "name": {
    "Code1": {
      "lang": "js",
      "body": "const x = {a: 1};\n  const y = 2;"
    }
  }
}
```

**一句话规则**：```` ```lang ```` 开围栏，```` ``` ```` 闭合；围栏内**原样保留**——缩进、换行、冒号、`-` 全部不参与解析，`pdformat` 也不会改动它。

### 要点

- **lang 可省略**：无 lang → 输出**只有 `body`** 字段；`body` 是单个字符串（含换行），不按行拆数组：

````pd
name:
```
plain text
```
````

```json
{
  "name": {
    "Code1": {
      "body": "plain text"
    }
  }
}
```

- **归属简化**：代码块只能属于顶层（顶层键或 Subject）。嵌套块（`- sub:`）里出现的代码块**仍归顶层键**：

````pd
name:
- sub:
  - x
```js
const a = 1;
```
````

```json
{
  "name": {
    "sub": {
      "Info1": [
        "x"
      ]
    },
    "Code1": {
      "lang": "js",
      "body": "const a = 1;"
    }
  }
}
```

- **打断 Info**：代码块前后的文本会分成两段（Info1 / Code1 / Info2）：

````pd
name:
- some
```
code
```
words
````

```json
{
  "name": {
    "Info1": [
      "some"
    ],
    "Code1": {
      "body": "code"
    },
    "Info2": [
      "words"
    ]
  }
}
```

- **键值不折叠**：`name: value` 后面跟代码块 → 不再折叠成字符串，变对象形态
- **未闭合围栏**：body 延伸到文件尾，宽容处理、不报错
- 顶层无键的代码块 → 归 `Subject1`；多个代码块编号递增 Code1 / Code2（每层独立）

🎯 **本节要点**：围栏内原样；`CodeN { lang?, body }`；只归顶层；打断 Info 段。

## 行内多冒号的处理

**你想做什么**：一行里出现好几个冒号（URL、时间），不想被误拆。

### 只有第一个冒号是分隔符

键值判定只认**行内第一个半角冒号**；它右边的冒号全是普通文本：

```pd
url: https://example.com:8443/path
```

```json
{
  "url": "https://example.com:8443/path"
}
```

值 `https://example.com:8443/path` 完整保留，不会在第二个冒号再拆一次。

### `:-` / `：-` 整行转义（普通冒号标记）

行内只要出现 `:-` 或 `：-`，**整行不识别任何键值**，这两个字符作为正文原样保留：

```pd
clock:- 12:30
```

```json
{
  "Subject1": {
    "Info1": [
      "clock:- 12:30"
    ]
  }
}
```

用途：`clock: 12:30` 这种"时间 + 列表"混写时防止误解析；也解释了为什么引用名不能以 `-` 开头（`:-` 已被保留）。

### 转义不影响同行的引用

`:-` 只负责"本行不拆键值"，同一行后面满足引用规则的 `:名称` 照常展开：

```pd
//!pd base
hello world

//!pd main
clock:- 12:30 :base done
```

```bash
pd2json file.pd main
```

```json
{
  "Subject1": {
    "Info1": [
      "clock:- 12:30 hello world done"
    ]
  }
}
```

🎯 **本节要点**：键值分隔 = 第一个半角冒号；`:-` / `：-` 整行转义；`:名称` 引用的识别独立于键值规则。

## 分隔线 `---`

**你想做什么**：一份文件里写多个互相独立的块，块与块之间"老死不相往来"。

### 作用：指针回根

`---` 是**块边界**：之前的父子关系全部清空，之后的键值/内容从根重新开始：

```pd
第一部: 内容
---
第二部: 内容
```

```json
{
  "第一部": "内容",
  "第二部": "内容"
}
```

### 分隔线后的无键内容 → 新 Subject

```pd
no man
can
kill: me
---
nobody
- like: you
```

```json
{
  "Subject1": {
    "Info1": [
      "no man",
      "can"
    ]
  },
  "kill": "me",
  "Subject2": {
    "Info1": [
      "nobody"
    ],
    "like": "you"
  }
}
```

- 第 1 段：`no man` / `can` 无键 → `Subject1`；`kill: me` 裸键值 → 顶层键
- `---` 之后：`nobody` 无键 → **新的** `Subject2`（编号自增）

### 对比记忆：空行无视 vs `---` 回根

| 行为 | 空行 | `---` |
| --- | --- | --- |
| 找爸爸 | 继续找，结构不变 | 强制回根 |
| Subject | 不新建 | 新建（SubjectN 自增） |

🎯 **本节要点**：`---` = 块边界 + 指针回根；之后的无键内容开新 Subject。

## 易踩坑清单

把前 8 章散落的坑 + 没问到的组合汇总在这里（全部已验证）：

1. **顶层 `-` 不能缩进**。文件开头或 `---` 后写带缩进的 `-` 行（如下）→ 语法错误 ```` `顶层 `-` 不允许缩进` ````（`pd2json` 带行号报错退出；`pdformat` 会自动去缩进修正）：

```pd
  - xxx
```

但注意区分：**顶层键下**的 `-` 缩不缩进都行（归键块，不算顶层）。
2. **裸键值行不找爸爸**。缩进再深也回根（见"多个键值"一节的反例）；要嵌套必须 `- 键:`。
3. **全角冒号 / 无空格冒号不是键值**（见"顶层键值"一节的两个坑）；`pdformat` 一键修正。
4. **重复键 → 后者覆盖前者**：`name1: a` 之后 `name1: b` → `{"name1":"b"}`。
5. **空值键 `key:` → 空对象 `{}`**，不是 null 也不是空字符串。
6. **`key: 值` 之后出现续行 / 子键 / 代码块 → 不再折叠成字符串**，统一变成对象形态。
7. **引用名不能以 `-` 开头**（`:-` 留给转义）；多段文件不指定段名 → 报错"必须指定段名"。
8. **Subject vs Info**：Subject = 顶层匿名对象容器（Subject1/Subject2…）；Info = 块内匿名数组（Info1/Info2…）；编号各自独立。
9. **内联 markdown 原样保留**：`**粗体**`、`` `代码` `` 转 JSON 时既不解析也不剥离。
10. **无限嵌套**：靠 `- 键:` 链；数组元素一行一个、无逗号。
11. **空行随便空**：没有 `---` 时，空多少行结构都不变。
12. **代码块专属坑**（见"代码块"一节）：只归顶层、打断 Info 段、未闭合围栏延伸到文件尾。

## 速查表

| 写法 | 含义 | JSON 结果 |
| --- | --- | --- |
| `//!pd 名称` | 段标记（可省略；多段必用） | — |
| `---` | 分隔线，指针回根 | 新块 / 新 Subject |
| `key: value` | 顶层键值（单条） | `"key": "value"` |
| `key:` + 续行 | 多行文本 | `"key": {"Info1": [...]}` |
| `- key: value` | 子键值（找爸爸嵌套） | 嵌套对象 |
| `- 内容` / `内容` | 内容行 | 压入 Info 数组 |
| `:名称`（前后空格） | 引用 | 编译期内联展开 |
| `:-` / `：-` | 整行转义（非键值非引用） | 原样文本 |
| ```` ```lang ```` ... ```` ``` ```` | 代码块 | `"CodeN": {"lang": ..., "body": ...}` |
