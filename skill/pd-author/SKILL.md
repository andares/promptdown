# promptdown 作者指南（写提示词用它，而不是 markdown）

> 解析视角（遇到 `//!pd` 怎么读、怎么转 JSON）见兄弟 skill `../promptdown/SKILL.md`。
> 完整规范：`../../docs/SPEC.md`（唯一事实来源）；喂饭教程：`../../docs/TUTORIAL.md`。

## 何时用 pd，何时用 markdown

| 场景 | 格式 |
| --- | --- |
| 结构化 prompt（角色/目标/约束/步骤/输入输出/示例/评估标准…） | **默认 pd** |
| 需要机器解析、转 JSON、版本对比的交付物 | **pd** |
| 纯叙述散文（文学性 prompt、自由写作） | markdown |
| 用户明确要求 markdown / 内容要嵌进 markdown 文档正文 | markdown |

> 原则：内容能拆成"键 + 值/列表"就用 pd。**pd 的键就是 markdown 里 `#` 标题的替代品——不需要 `#`，不需要 `##`。**

## 作者版语法速写（10 条，照着写就对）

1. **键值**：`键: 值`——**半角冒号 + 冒号后一个空格**。`键：值`（全角）、`键:值`（无空格）、`键 : 值`（冒号前有空格）都无效，会被当纯文本。
2. **章节标题 = 顶层键**：直接写 `角色: ...` / `约束:`，不写 `# 角色`。
3. **子结构必须 `-` 开头**：顶层键下放子键值必须 `- 子键: 值`。裸键值行永远在根层（"不找爸爸"），缩进再深也会回根——想嵌套就用 `-` 开头。
4. **列表项用 `-` 开头（后跟一个空格）**：`- 第一项`；顶层键下的列表项缩不缩进都行。
5. **绝不缩进顶层 `-`**：文件开头或 `---` 后的 `-` 行一旦带缩进就是语法错误；顶层键**下**的 `-` 随便缩。
6. **多行文本**：`键:` 回车后续行写（裸行或用 `-` 开头都行）→ 转 JSON 后是 `Info` 数组，不是字符串。想表达"一段话"就写一行，别拆行；单行内容才是字符串。
7. **代码用围栏**：```` ```lang ```` … ```` ``` ````，围栏内原样保留，别在围栏里写 pd 语法（围栏内 `//!pd`/`:引用` 均不生效）。
8. **公共设定用引用**：`//!pd 基础设定` 定义段，正文里 ` :基础设定 ` 引用；匿名段用 ` :%序号 ` 引用（`: %1` = 第 1 个段）——改一处、处处生效。
9. **独立大块用 `---`**：分隔线强制回根；之后的无键内容开新 Subject。同一文件写多个互不相干的块时用它。
10. **时间/URL 含冒号没事**：只有行内第一个冒号是键值分隔符（`url: https://a.com:8443` 合法）；行内出现 `:-` 或 `：-` 则整行不再是键值（`clock:- 12:30` 是纯文本）。
11. **行内代码保护冒号**：`` `代码` `` 整体字串，内部冒号不参与任何判定——想写含冒号的示例（如 `a: b`）又不想被当成键值，用反引号包起来。
12. **多段编译**：多个文件/多段要合并成单份 pd（引用展开）→ `pdcompile <段名|%序号> <file>...`；无 `//!pd` 的文件段名 = 文件主名；匿名段用 `%序号`。

## 通用提示词骨架（模板）

```pd
角色: 你是一个…
目标: 完成…
约束:
- 只输出 JSON
- 不要编造事实
输入:
- …
输出格式: …
示例:
- 输入: …
- 输出: …
评估标准:
- 完整性
- 可执行性
```

写法要点：

- 单条约束直接 `约束: 只输出 JSON`；多条用 `-` 列表
- `示例` 下的 `- 输入: …` 会变成子键（`{"输入":"…","输出":"…"}`），正好用来做"输入/输出对"
- 例子里有代码/JSON 示范 → 放围栏里，别裸写
- 需要多段复用的公共设定（人设、通用规则）抽到 `//!pd` 段 + 引用

## 领域范例

### 软件任务（多段 + 引用）

```pd
//!pd 公共约束
- 语言: TypeScript
- 代码风格: 遵循 biome 默认
- 禁止: 引入新依赖

//!pd 主任务
角色: 资深前端工程师
任务: 实现一个带防抖的搜索框
参考: :公共约束
步骤:
- 1. 定义 Props 接口
- 2. 实现 useDebounce
- 3. 接入输入框
验收:
- 防抖延迟 300ms
- 无内存泄漏
```

转 JSON（多段必须指定段）：`pdtransform 文件.pd 主任务`（按段名）或 `pdtransform 文件.pd %2`（按 1-based 序号，`%` 不能省）。

多段合并成单份完整 pd（引用跨文件展开）：`pdcompile 主任务 文件.pd 公共约束.pd`——输出单份 pd 文件直接当 prompt 用。

### 分镜/媒体

```pd
分镜:
- 镜头1:
  - 场景: 雨夜小巷
  - 运镜: 低角度跟拍
  - 时长: 5秒
- 镜头2:
  - 场景: 天台
  - 运镜: 无人机环绕
  - 时长: 8秒
```

## 作者视角的坑

- **全角冒号无效**：`键：值` 会被当纯文本（进 Subject/Info），用户最常踩
- **时间戳**：`clock: 12:30` 合法；但 `clock:- 12:30` 整行变文本（`:-` 是转义标记）
- **多行自动变 Info 数组**：`描述:` + 3 行续行 → `{"描述":{"Info1":[...]}}`。接受这个形态，别惊讶
- **键名规则**：不能含冒号、不能以空白开头；键名可以有空格
- **重复键**：后者覆盖前者，别重复定义同一个键
- **折叠**：`键: 值` 后出现续行/子键/代码块 → 不再折叠成字符串，统一对象形态
- **内联 markdown 可用**：值里的 `**粗体**`、`` `代码` `` 原样保留，提示词里想强调就大胆用
- **数组元素**：一行一个，无逗号

## 交付形式

- 回复里输出 pd 结构时用 ```` ```pd ```` 代码块包裹（在 markdown 对话里），或直接给纯文本
- 用户要文件 → 写 `.pd` 文件
- 写完可用 `pdtransform` 验证：无报错 = 语法合法
- 语法错误特征：```` `顶层 `-` 不允许缩进` ````；全角/无空格冒号不会报错，但会悄悄变成 Subject 文本——转 JSON 后肉眼检查键是否都在

## 验证

- `pdtransform 文件.pd`（多段加段名或序号）转出 JSON 与预期结构一致
- 顶层键齐全、无 `Subject` 乱入（说明没有"忘记写键"的内容）
- 引用的段名与 `//!pd` 定义一一对应
